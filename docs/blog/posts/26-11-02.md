## 题意

有 $N$ 名玩家，其中恰好有 $M$ 名狼人、$L$ 名说谎者。第 $i$ 名玩家会说一句针对玩家 $p_i$ 的话：

- `+p` 表示“玩家 $p$ 是人类”；
- `-p` 表示“玩家 $p$ 是狼人”。

狼人中说谎的人数至少为 $1$，但不能是 $M$，也就是至少一只狼说谎，至少一只狼说真话。

若有多组合法答案，输出狼人编号降序后字典序最大的一组。无解输出 `No Solution`。

## 从“真假”人数入手

设玩家 $i$ 的身份为

$$
x_i=
\begin{cases}
0,&\text{人类}\\
1,&\text{狼人}
\end{cases}
$$

对某个玩家 $j$，所有针对他的声明共同决定他能贡献多少名说谎者。

- 如果 $j$ 是人类，那么 `-j` 是假话，贡献数量为所有 `-j` 的条数；
- 如果 $j$ 是狼人，那么 `+j` 是假话，贡献数量为所有 `+j` 的条数。

代码里用 `c0[j]` 记录 `-j` 的条数，用 `c1[j]` 记录 `+j` 的条数。确定 `j` 的身份后，新增的说谎人数就是

```text
addLie = (x[j] == 1 ? c1[j] : c0[j]);
```

这样一来，总说谎人数不需要等到整组身份确定后再扫描全部玩家，而可以随着目标玩家的身份确定逐步累加。

## 判断一句声明是否为假

玩家 $i$ 的声明对象是 $p_i$。令

$$
y_i=
\begin{cases}
x_{p_i},&i\text{ 的声明是 }+p_i\\
1-x_{p_i},&i\text{ 的声明是 }-p_i
\end{cases}
$$

那么 $y_i$ 正好表示第 $i$ 句声明是否为假。

- `+p` 为假，说明 $p$ 是狼人，因此 $y_i=x_p$；
- `-p` 为假，说明 $p$ 是人类，因此 $y_i=1-x_p$。

如果玩家 $i$ 本身是狼人，那么 $y_i=1$ 时，他就是一个“说谎的狼”；$y_i=0$ 时，他是一只“说真话的狼”。

## DFS 状态

从编号 $N$ 往 $1$ 决定身份。编号大的玩家先尝试成为狼人，所以第一次搜到的合法解就是字典序最大的答案。

搜索函数如下：

```text
dfs(k, wolfCount, curLie, wolfLie, pending)
```

| 参数 | 含义 |
|---|---|
| `k` | 玩家 $1\ldots k$ 尚未确定，玩家 $k+1\ldots N$ 已经确定 |
| `wolfCount` | 已经确定的狼人数 |
| `curLie` | 已经确定的说谎人数 |
| `wolfLie` | 目前确定的、在说谎的狼人数 |
| `pending` | 已确定的狼说过、但目标身份尚未确定的声明数 |

`pending` 是这份写法里最需要小心的地方。例如玩家 $8$ 是狼，他说 `+3`。搜索还没有处理玩家 $3$，这句话暂时无法判断真假，只能先挂起。等确定玩家 $3$ 的身份后，再计算它是否为假，并把 `pending` 减一。

## 确定一个玩家身份后的更新

处理玩家 $k$ 时，令他的身份为 `val`。

第一步，处理说谎人数：

```text
int addLie = (val == 1 ? c1[k] : c0[k]);
curLie += addLie;
```

第二步，处理所有以 $k$ 为声明对象的玩家：

```text
for (int i : rev[k]) {
    // 判断玩家 i 的声明真假
}
```

如果声明者 $i>k$，他的身份已经确定。当 $i$ 是狼时，现在终于可以判断这条声明真假：

```text
int y = sgn[i] ? val : (1 - val);
wolfLie += y;
pending--;
```

如果 $i=k$，也就是玩家评价自己，此时也能直接判断。

第三步，如果玩家 $k$ 是狼，还要看他自己的声明：

- 目标 $p_k>k$，目标身份已经确定，立即判断真假；
- 目标 $p_k<k$，目标身份尚未确定，令 `pending++`；
- 目标 $p_k=k$，自指声明已经在处理 `rev[k]` 时结算。

每条声明只会在一个时刻被结算，不会重复进入 `wolfLie`。

## 剪枝

### 狼人数上下界

```text
if (wolfCount > m) return false;
if (wolfCount + k < m) return false;
```

前一句表示已经超过总数。后一句表示即使剩下 $k$ 个人全是狼，也凑不够 $M$ 只狼。

### 说谎人数的上下界

预处理：

```text
minSum[i] = minSum[i - 1] + min(c0[i], c1[i]);
maxSum[i] = maxSum[i - 1] + max(c0[i], c1[i]);
```

`minSum[k]` 表示玩家 $1\ldots k$ 最少能贡献多少名说谎者，`maxSum[k]` 表示最多能贡献多少名。

如果当前数量加上上下界后已经不可能等于 $L$，直接返回：

```text
if (curLie + minSum[k] > l) return false;
if (curLie + maxSum[k] < l) return false;
```

### 说谎狼数量的上下界

题目要求

$$
1\le\text{说谎狼数}\le M-1.
$$

当前还需要选出 `need = M - wolfCount` 只狼。对于玩家 $1\ldots k$，如果他会成为狼，可以估算他的声明为假的可能性：

- 声明对象已经确定，真假可以直接算出；
- 声明对象是他自己，真假也能直接算出；
- 声明对象还在 $1\ldots k$ 中且不是自己，真假暂时可能是 $0$ 或 $1$。

把每条候选声明的“最小可能值”排序，取前 `need` 个作为 `minAdd`。若

```text
wolfLie + minAdd > m - 1
```

说明未来狼人即使都尽量说真话，仍然无法留下至少一只说真话的狼。

同理，把“最大可能值”从大到小排序，取前 `need` 个作为 `maxAdd`。若

```text
wolfLie + pending + maxAdd < 1
```

说明无论后面怎么安排，都不可能产生一只说谎的狼，可以直接剪枝。

### 分支时的即时剪枝

递归进入下一层前，代码还会再检查一次 `newCurLie`、`newWolfLie` 和 `newPending`。这些判断都只使用当前已经能确定的信息，因此不会误删合法答案。

## 正确性

先看说谎人数。玩家 $j$ 的身份确定为人类或狼人后，所有针对 $j$ 的声明真假完全相同。人类的 $j$ 会让全部 `-j` 为假，狼人的 $j$ 会让全部 `+j` 为假。所以 `c0[j]` 和 `c1[j]` 正好穷尽了 $j$ 对总说谎人数的贡献。

再看 `pending`。一条狼的声明只有在声明者身份已知后才能产生影响。若目标已经确定，就立即结算；否则挂入 `pending`。目标确定时，挂起的声明会被结算并移出。因此每条声明恰好结算一次。

搜索中的剪枝都基于“当前值”和“未来可能值的上下界”。一旦合法解所需的数量落在区间外，这把分支就不可能产生答案；反过来，所有判断都没有排除仍然可行的状态。

最后，玩家编号从 $N$ 到 $1$ 依次决定，并且每次先试狼人。两个答案第一次出现不同的位置一定在较大的编号上，因此先搜到的合法解就是题目要求的最大降序序列。

## 复杂度

预处理的时间复杂度是 $O(N)$。

DFS 每个结点会扫描当前未确定的玩家并排序，单结点最坏为 $O(N\log N)$。搜索本身仍是指数级，最坏时间复杂度为

$$
O(2^N N\log N).
$$

空间复杂度为

$$
O(N),
$$

主要来自递归栈和临时数组。

这些数字只是最坏上界。`minSum/maxSum`、说谎狼数量下界以及 `pending` 的即时结算会消掉大量不可能分支。这个写法的实际效率很依赖剪枝效果和输入结构。

## 易错点

`sgn[i]` 为真表示 `+p`，为假表示 `-p`。代码里的 $y$ 是“这句话是否为假”，不要把它当成真话标记。

`c0` 记录的是负数声明的数量，`c1` 记录的是正数声明的数量。玩家 $k$ 是人时使用 `c0[k]`，是狼时使用 `c1[k]`。

修改 `wolfLie` 时，要同时看声明者的身份和目标身份。声明者不是狼时，这句假话不计入“说谎的狼”。

`pending` 必须在目标身份确定时减一。漏减会重复计算，提前结算则可能把原本未确定的声明算错。

分支顺序不能轻易交换。先试狼人才能让第一次找到的答案满足题目要求的最大字典序。
